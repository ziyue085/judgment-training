# 揭晓协议（Reveal Protocol）

锁定预测之后，训练从"盲测"转入"对答案"。这一步最容易出错的地方，不是
**算不算命中**，而是**拿来对答案的那个数本身可不可靠**。

本文件规定：揭晓时用什么来源、怎么核对口径、遇到统计修订怎么办。

---

## 一、为什么需要一个协议

一个数值型历史预测，命中判定完全取决于"真实值"取哪一个数。实践中至少存在四种
陷阱，会让一次本该诚实的复盘失真：

1. **来源层级过低**：用新闻转述、百科条目、自媒体文章当"真值"。
   这些数字可能被简化、四舍五入、甚至抄错。
2. **口径不一致**：预测用的是"常住人口口径、当年价、全市"，
   对答案时取了"户籍人口口径、不变价、市辖区"。数字对不上，但没人是错的。
3. **期间错位**：预测的是 2013 年全年，揭晓时取的是 2012 年或 2014 年的值。
4. **修订黑洞**：统计值后来被修订。当时公布的是 790，修订后是 812，
   预测区间是 [700, 800]。用哪个数判命中，结论完全相反。

本协议逐一处理这四类问题。

---

## 二、来源层级（按对象类型）

规则层 `REVEAL_SOURCE_TIERS` 定义了优先来源。落在层级外的来源可以作补充，
但不能单独作为对答案的依据。

### 城市

| 层级 | 来源 | 说明 |
|---|---|---|
| 一级（首选） | 统计局《国民经济和社会发展统计公报》 | 年度、口径明确、含常住人口与当年价说明 |
| 一级 | 统计年鉴 / 统计数据库 | 可回溯修订序列 |
| 一级 | 政府 / 统计局官网数据发布 | 与公报一致 |
| 二级（补充） | 政府工作报告、部门专项公报 | 常用于分行业数据 |
| 三级（仅参考） | 新闻、百科、研究论文引用 | **不得单独作为真值** |

### 企业

| 层级 | 来源 | 说明 |
|---|---|---|
| 一级（首选） | 年报 / 经审计财务报表 | 含会计师意见与附注 |
| 一级 | 交易所法定披露 | 与年报一致 |
| 一级 | 10-K / 20-F 等法定文件（美股/中概股） | SEC 备案原文 |
| 二级（补充） | 招股说明书、业绩预告、临时公告 | 注意预告 ≠ 实际 |
| 三级（仅参考） | 财经媒体报道、券商研报 | **不得单独作为真值** |

规则层反应：来源不含层级关键词 → `REVEAL_SOURCE_TIER_LOW`（WARN）。
**该警告不阻止复盘**，但要求补充一级来源，或在对答案时显式标注"来源为二手"。

## 三、口径核验（命中判定的前提）

**口径不一致时，命中判定无效。** 这不是"打个折"，而是直接作废。

规则层检查 `actual_caliber` 与 `base_caliber`：

- 不相等 → `REVEAL_CALIBER_MISMATCH`（BLOCK）。
- 常见不一致维度：
  - **人口分母**：常住人口 / 户籍人口
  - **价别**：当年价 / 不变价（可比价）
  - **地域**：全市 / 市辖区 / 县域
  - **时期口径**：全年 / 年末 / 年平均
  - **企业口径**：合并报表 / 母公司报表；归母净利润 / 净利润

期间核验分两层（v0.2.3 补齐第二层）：

1. `actual_period` 与 `base_period` 相同 → `REVEAL_PERIOD_MISMATCH`（WARN），
   大概率把基期值当成了结果值。
2. **结果期末必须等于 `forecast_to`** —— 这是 v0.2.3 新增的硬闸门：
   不一致 → `REVEAL_TARGET_PERIOD_MISMATCH`（**BLOCK**）。

第 2 条此前完全缺失，后果很实际：

```text
预测目标期：2013-12-31
结果记录：实际 620（2012 年公报）        ← 期间完全对不上
```

620 与预测的匹配程度毫无意义 —— 它是**另一年**的数。数字再准，评的也不是同一件事。
校验用 `period_matches_forecast_target(actual_period_end, forecast_to)`：
两端都是完整日期时要求同日；只写年份（如「2013」）则退化为同年比较，旧档案仍兼容。

逐字段必填项（缺一即 BLOCK）：`actual_value` / `actual_unit` / `actual_caliber` /
`actual_period` / `source`。

建议同时给出 `actual_period_start` / `actual_period_end`：

| 字段 | 作用 | 例 |
|---|---|---|
| `actual_period` | 人类可读的期间描述 | `"2013"` |
| `actual_period_start` | 区间起点（可选） | `"2013-01-01"` |
| `actual_period_end` | **区间终点，与 `forecast_to` 比对** | `"2013-12-31"` |

> 用户只说"实际是 812"（裸数值）→ `REVEAL_RECORD_MINIMAL`（WARN）。
> 若当前阶段已是 `REVEAL`，则按正式揭晓处理，逐字段核验，缺哪个报哪个。

## 四、统计修订处理

统计值不是终值。GDP、财政收入、人口等会被后续普查或口径调整追溯修订。

因此揭晓记录**必须能容纳两个数**：

| 字段 | 含义 | 必填条件 |
|---|---|---|
| `as_reported_then` | 当时（预测期限后首次）公布的值 | `revision_status` 为 `revised` / `final` 时**必填** |
| `latest_revised` | 目前最新修订值 | 可选 |
| `revision_status` | `initial` / `revised` / `final` / `unknown` | 缺 → WARN |
| `published_at` | 首次公布时间 | 缺 → WARN |

规则层：`revision_status ∈ {revised, final}` 且无 `as_reported_then`
→ `REVEAL_REVISION_UNRECORDED`（WARN）。

### 判定用哪个数？

**铁律：不得只留对预测有利的那个。**

标准做法——**两个数都算**，并分别报告：

```
命中判定 A（用当时公布值 as_reported_then）：反映"当时能不能算对上"
命中判定 B（用最新修订值 latest_revised）：反映"用后见之明看是否对"
```

两者不一致时，**必须在对答案时明说**：
「按当时公布的 790 判定为命中；按修订后的 812 判定为未命中。」
不得只报其中一个。过程与结果分离的复盘原则（见 `methodology.md`）同样适用于此：
**改口径、改修订版来"救回"一次未命中，是最严重的复盘作弊。**

### 无修订状态的旧案

若揭晓时无法确定修订状态 → 写 `"unknown"`，并在记录中标注
"修订状态不明，本次命中判定按现行值处理，未来修订可能导致结论变化"。

## 五、位置与顺序（揭晓在流程中怎么放）

揭晓**只发生在用户显式授权之后**（SKILL.md 铁律 8）：用户明确说出
"这是我的最终预测，可以揭晓"，教练才进入 `REVEAL`。

揭晓的边界纪律：

1. **只揭晓到预测期限**，不越界剧透下一段（例如预测到 2013，就不说 2015 发生了什么）。
2. **只揭晓预测涉及的指标**，不顺手给出别的指标的真实值。
3. **先记录再评判**：先把结果记录写全（含口径、来源、修订），再谈命中。
4. **不解释因果**：揭晓阶段只给"是什么"，为什么留到 `POSTMORTEM`。

揭晓记录的结构（写入档案）：

```json
{
  "outcomes": {
    "财政支出": {
      "actual_value": 812,
      "actual_unit": "亿元",
      "actual_caliber": "常住人口口径、当年价、全市",
      "actual_period": "2013",
      "actual_period_end": "2013-12-31",
      "source": "神木县 2013 年国民经济和社会发展统计公报",
      "published_at": "2014-03",
      "revision_status": "revised",
      "as_reported_then": 790,
      "latest_revised": 812
    }
  }
}
```

> **`actual_value` 才是复盘读的那个字段。** 旧档案里可能只有裸的 `actual`，
> 复盘会把它当兼容回退读进来；但新记录一律写 `actual_value`。
> v0.2.3 修的就是"揭晓写 `actual_value`、复盘只读 `actual`"导致的
> 「揭晓成功、复盘却当没揭晓」。

## 六、揭晓阶段的前台纪律

`check_reveal()` 会返回一长串字段级发现，但**前台不要念清单**。

- 字段齐全 → 只确认一句：「口径与来源已核对，可以进入复盘。」
- 有 BLOCK（缺字段 / 口径不符）→ 只说最关键的那一条，请用户补。
  例：「结果口径写的是'户籍人口'，但预测用的是'常住人口'，这两个对不上，先确认口径。」
- 有 WARN（来源层级低 / 缺修订状态）→ 一句带过，标记后继续。

完整核对结果留在档案，供复盘引用。

## 七、常见错误对照

| 错误做法 | 后果 | 正确做法 |
|---|---|---|
| 用百科数字对答案 | 值可能失真，命中判定不可信 | 回到统计公报 / 年报一级来源 |
| 口径不一致照算命中 | 命中判定无效 | 先统一口径；不统一则作废该次判定 |
| 结果期与预测目标期不一致照算命中 | 拿别的年份结算，命中判定无效 | 先对齐 `actual_period_end` 与 `forecast_to` |
| 揭晓写 `actual_value`、复盘读 `actual` | 揭晓成功但复盘当没揭晓 | 复盘主读 `actual_value`，`actual` 仅作旧档回退 |
| 只留修订后的值 | 前视/美化复盘 | 同时保留 `as_reported_then` 与 `latest_revised` |
| 只留当时公布值 | 忽略后续修订带来的结论变化 | 两个都报 |
| 揭晓时顺带剧透下一段 | 破坏后续训练 | 严格止于预测期限 |
| 揭晓即点评对错 | 过程与结果混为一谈 | 揭晓只记录，复盘再评判 |
